## [2.0.2] - 2026-09-22

### Security

- **DNS rebinding is closed for URL downloads** (`urlToBase64`, `imageToBase64` with a
  URL, `downloadImage`, `downloadVideo`, `downloadMedia`). 2.0.1 validated a name by
  resolving it, then let fetch resolve it again to connect; a name answering public
  and then private passed the check and connected inward. Downloads now connect
  through an undici `Agent` whose lookup checks every address it hands the socket.
  Refusals carry `code: 'ESSRFBLOCKED'` and `validateImageUrl`'s message. This was
  2.0.1's documented known limitation (docs/DECISIONS.md #12, #15).
- **Every DNS answer is checked, not the first.** A name with one public and one
  private record passed `validateImageUrl`.
- **IPv6 ranges are matched as ranges.** `/^fd00:/` and `/^fc00:/` passed
  `fd12:3456::1` and the rest of `fc00::/7`; `/^fe80:/` missed the rest of
  `fe80::/10`. Multicast `ff00::/8` is now blocked too.
- **IPv6 addresses embedding an IPv4 one are judged by that IPv4**, in any spelling.
  Node's URL parser rewrites `https://[::ffff:127.0.0.1]` to `[::ffff:7f00:1]`, and
  only the dotted form was recognised, so the hex form of loopback passed; NAT64
  (`64:ff9b::/96`), IPv4-translated and IPv4-compatible forms are covered as well.
- IPv4 carrier-grade NAT (`100.64/10`), benchmarking (`198.18/15`), `192.0.0/24` and
  multicast/reserved (`224/3`) are blocked.
- The DNS lookup in `validateImageUrl` has a 10 s deadline; it had none.
- **IPv6 tunnel addresses are judged by the IPv4 they carry.** 6to4 (`2002::/16`) and
  Teredo (`2001::/32`, client address bit-inverted) passed the blocklist, so
  `https://[2002:7f00:1::1]` — 6to4 around 127.0.0.1 — was accepted. Deprecated
  site-local `fec0::/10` is now blocked too. Found by the pre-release security review.
- **Signed result URLs no longer reach logs or error messages.** `urlToBase64` logged
  the full URL and put it in its error message; BFL result links carry their
  signature in the query string. They now show origin and path, with the query
  replaced by `?[redacted]`. Found by the pre-release security review.

All five are ported from stability-ai-api 1.0.1, which found them in this same code.

### Added

- `createGuardedLookup` and the `AllAddressResolver` type in `bfl-api/utils`.
- `undici` as a runtime dependency, pinned to major 7: an undici 8 `Agent` is rejected
  by Node 22's and 24's global fetch (`UND_ERR_INVALID_ARG`); see DECISIONS #15.

## [2.0.1] - 2026-09-22

Released as 2.0.1 rather than 2.0.0: `bfl-api@2.0.0` was published on
2022-12-06 and subsequently unpublished, and npm keeps a permanent tombstone for
unpublished versions — that exact version string can never be reused for this
package name. The tombstone is invisible in the `versions` list and in
`npm view <pkg>@<ver>`; it shows only in the registry's `time` map, which still
carries a `2.0.0` entry the `versions` map does not. Nothing about the release
itself changed; this entry is the 2.0.0 work under the first usable number.

Brings the wrapper up to the current BFL API (spec snapshot
`docs/openapi-snapshot-2026-09-20.json`). Twenty-one endpoints, video support,
and a CI check that fails the build when the live spec drifts from the wrapper.
Design rationale in `docs/DECISIONS.md`.

### Added

- **Native `fetch` replaces axios** (`src/http.ts`). No runtime HTTP dependency;
  `axios` and its 8 transitive packages (2.4 MB) are gone. The module
  reimplements what axios gave implicitly — throwing on non-2xx, byte ceilings
  enforced *while streaming*, a bounded and re-validated redirect chain, and
  typed transport errors. Rationale: `docs/DECISIONS.md` #11.
- `BflNetworkError` (`.code`, `.retryable`), `BflTimeoutError` (`.timeoutMs`)
  and `BflTaskError` (`.taskStatus`, `.taskId`) exported alongside
  `BflHttpError` (which gained `.body`, the parsed error payload).
- **FLUX.2 [max]**, **[klein] 4B**, **[klein] 9B**: `generateFlux2Max`,
  `generateFlux2Klein4b`, `generateFlux2Klein9b`.
- **FLUX Tools (image)**: `deblurImage`, `eraseImage` (`dilate_pixels`),
  `outpaintImage` (canvas `width`/`height`, `reference_offset_x/y`, `auto_crop`,
  `mode`), `virtualTryOn` (`person`, `garment`).
- **FLUX 3 video**: `generateFlux3Video` (discriminated union on `mode`:
  `t2v` / `i2v` with `keyframes` / `v2v` with `start_video` / `draft_enhance`
  with `draft_cache`), `editVideo`, `upscaleVideo`. The CLI saves video as
  `.mp4` and defaults `--timeout` to 900 s for it.
- **FLUX 1.1 [pro] Ultra finetune**: `generateFluxProUltraFinetuned`.
- **Finetune utilities**: `getFinetuneDetails`, `deleteFinetune`
  (CLI `--finetune-details`, `--delete-finetune <id> --yes`).
- `user`, `webhook_url`, `webhook_secret` forwarded on every endpoint whose
  schema declares them (`CommonRequestFields`).
- `image_prompt` on FLUX.1 [dev]; `guidance`/`steps` on FLUX.2 [flex];
  `aspect_ratio`/`prompt_upsampling` on Kontext.
- `webp` accepted as `output_format` everywhere.
- `BflHttpError` (`status`, `retryAfter`) thrown for HTTP failures.
- `MODELS` registry (`path`, `label`, `media`, `defaultOutputFormat`),
  `MODEL_FIELDS`, `FLUX3_VIDEO_MODE_FIELDS`, `getModelInfo`,
  `ModelConstraint.fields` for 2.0-era parameters.
- `scripts/check-spec-drift.ts` (`npm run check:spec`, `check:spec:control`,
  `check:spec:snapshot`) and `npm run verify`; CI runs the control and the live
  check before the tests.
- `validateVideoPath`, `videoToBase64`, `downloadMedia`, `downloadVideo` in
  utils. CLI `--dry-run` elides base64 payloads.

### Changed

- **Requires Node 22+** (`engines.node: >=22.0.0`, was `>=18.0.0`); build target
  ES2023, CI on Node 22. Node 18 is EOL, and 22 gives `fetch`,
  `AbortSignal.timeout` and `ReadableStream` without an experimental warning
  (verified on 22.23.2).
- **Retries are classified by error type, not message text.** Transient means
  `BflHttpError` 502/503, a retryable `BflNetworkError`, or `BflTimeoutError`;
  terminal task failures are `BflTaskError` and are never retried. This
  restores network-error retries, which the README documented but 1.x never
  performed — `err.message.includes('ECONNRESET')` never matched axios, whose
  message reads `socket hang up`. See `docs/DECISIONS.md` #13.
- Timeouts are idle-based (reset on each chunk) rather than total, so a slow but
  progressing video download is no longer at risk of being cut off. The polling
  GET, which had no timeout at all, now has one (30 s).
- **`generateFlux2Pro` no longer sends `prompt_upsampling`.** The API replaced
  it with `disable_pup` (upsampling on by default). `Flux2Params` is now the
  union of `Flux2ProParams` \| `Flux2FlexParams` \| `Flux2KleinParams`.
- **Kontext `input_image` is optional** (text-only generation); the wrapper
  used to throw without it.
- **Generation methods return `SubmitResult`** (`id`, `polling_url`, `cost`,
  `input_mp`, `output_mp`, or `status`/`webhook_url` in webhook mode) instead
  of `TaskResult`.
- **`TaskResult.status` is the full `TaskStatus` union** (`Task not found`,
  `Pending`, `Reasoning`, `Generating`, `Request Moderated`,
  `Content Moderated`, `Ready`, `Error`); gained `progress`, `details`,
  `preview`, `cost`. `waitForResult` continues through `Reasoning`/`Generating`,
  throws immediately on `Task not found`, treats `Request Moderated` as
  terminal (it was polled through before), reads the error from
  `details.error`, and honours `Retry-After` on transient polling errors.
- **Only fields the caller sets are sent**, so server defaults apply; the
  wrapper no longer forces `prompt_upsampling: true` on FLUX.2.
- **CLI file extension follows the server default** when `--output-format` is
  omitted — Kontext, deblur, erase and outpaint output is saved as `.png`
  (Kontext was PNG data named `.jpg` in 1.x). Output directory is per model key.
- CLI range validation now comes from `validateModelParams` (one table for CLI
  and library) instead of a parallel hand-written validator. Selecting two model
  flags is an error rather than first-wins.
- `MODEL_CONSTRAINTS` per-model `safetyTolerance` reflects the API: 0–6 FLUX.1,
  0–5 FLUX.2 / tools, 0–4 video.
- API-key help text points at `https://dashboard.bfl.ai/`.
- Releases are manual (`version` bump, this file, `npm run verify`,
  `npm publish`). semantic-release, its plugins, `.releaserc.json` and the
  release workflow are removed; `.github/workflows/ci.yml` verifies every push.

### Removed

- `axios` from `dependencies`. Runtime deps are now `commander`, `dotenv`,
  `winston`.
- `Flux2Params.prompt_upsampling` for [pro]/[max] (see Changed).
- The Kontext `input_image is required` error.
- semantic-release and its six plugins from `devDependencies`.

### Fixed

- `Task not found` no longer polls until timeout.
- `webp` no longer rejected client-side while the server accepts it.
- 502/503 with `Retry-After` on the polling URL waits the requested interval
  instead of the fixed backoff.
- `getResult(id)` without a polling URL now explains the 404 the global host
  returns for a regionally-served task instead of echoing "HTTP 404". The CLI
  writes `polling_url` into every metadata file and `--get-result` takes
  `--polling-url` (found live: a task submitted via `api.bfl.ai` was served
  from `api.eu2.bfl.ai`).
- A poll that answers HTTP 422 with a task body (`{status: "Error", details:
  {error}}` — video endpoints do this) is now returned as the result, so
  `waitForResult` reports `details.error` instead of "Request failed with
  status code 422" (found live on v2v; see `docs/LIVE-BATTERY-2026-09-21.md`).
- The CLI downloads a draft render's `draft_cache` bundle beside the video
  (`<name>.draft.bin`) so `--video-mode draft_enhance --draft-cache` works
  after the signed URL expires; the path is recorded in the metadata file.

### Security

- **Redirects are re-validated.** `validateImageUrl` checked only the URL it was
  given while axios followed up to five redirects unchecked, so a URL that
  passed the SSRF check could `302` to an internal address — including an
  https → http downgrade — and the body was returned. Every hop now goes back
  through the same check before being followed. Demonstrated against a local
  redirect-to-loopback server prior to the fix.
- **`urlToBase64` validates its own argument.** It is exported, so calling it
  directly bypassed SSRF validation entirely; only `imageToBase64` validated
  before delegating.
- **Response size ceilings are enforced mid-stream.** Previously the length was
  checked after the whole body had been buffered, which is not a limit. A
  hostile or misbehaving endpoint can no longer force unbounded allocation.
- Known limitation, unchanged: DNS rebinding is narrowed but not closed —
  see `docs/DECISIONS.md` #12.
